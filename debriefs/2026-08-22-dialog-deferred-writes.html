Debrief: dialog deferred writes

Date: 2026-08-22 · Report: reports/2026-08-22-dialog-deferred-writes-review.html

The what

A diff that makes the task dialog's Done button feel instant was reviewed before merge. The review found two ways you could lose edits without any error: renaming a subtask and clicking Done, or typing in the title/notes and clicking Archive. Both were fixed. Everything else in the diff checked out and is actually faster than what it replaced.

The why

Browsers move focus when you press a mouse button down, not when you release it. The diff armed its "we're closing, stop writing" flag on pointerdown to keep blur handlers from writing mid-dismiss — correct instinct, but the code then tried to read "what was being edited" at click time, one step too late. Focus had already moved, so the reader looked where the edit no longer was. The fix moves the reading to pointerdown too: capture and suppress happen in the same event, so they can never disagree about timing.

The how

The mechanism is a two-phase write pipeline. Phase one (capture) runs while the DOM is guaranteed alive: collectPending() snapshots field values from refs, identifies a focused subtask input via data-subtask-id, and drains the new-subtask draft input. It runs either on pointerdown (armClose) or inline in close for keyboard/dismiss paths where focus has not moved. Phase two (write) runs inside one setTimeout(0) after unmount, ordered: subtask rename, draft creation, field commit, then any trailing action like Archive's mutation — order matters there so the text commit targets the task before it archives. Suppression is single-owner: the blur handler's deferred write checks closingRef and yields if armed, and pendingRef is nulled on consumption, so each edit produces exactly one mutation even across double-clicks or a second dismiss call. Delete deliberately captures nothing because its writes are moot; it uses a suppress-only armer. The tradeoff accepted with uncontrolled inputs: titles do not re-sync from other devices mid-edit until remount — invisible single-user, visible in true multi-user sessions.
